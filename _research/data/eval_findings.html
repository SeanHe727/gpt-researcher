一句话结论

unsupported_claim 长期报出 45–66% 的"无据断言率"，看起来是 agent 在编造内容， 有机制解释、有理论支撑、故事自洽。它是假的。 真实原因是评分前把证据截断到 4000 字符，而管线给出的 context 有 32–44k 字符。 给全量证据，29 条断言全部有据。

与此同时，真正的架构缺陷在一个从未被测量的地方：抓取层。 权威源（.gov、学术出版商）的抓取失败率是普通源的 3.2 倍， 而源质量指标恰好把这些从未读到的源计入了平均分——指标在替管线掩盖缺陷。

方法论教训

一个 4000 的常量，制造了一个看起来完全合理的"架构缺陷"：45% 的无据率、有机制解释（抓取层丢数据源）、 有理论支撑（写作 prompt 强制篇幅与数字）。整个故事自洽到可以直接写进报告。

如果不做这个只改一个变量的消融，这个假发现会一路进 PR、进简历、进面试。 结论的有效性受制于测量的可靠性——这不是口号，是这次真实发生的事。

饱和从哪来

citation_faithfulness 的满分不是优秀，是分母太小：报告的参考文献平均只列 3.67 个域名，而实际用了 14.3 个源。 而且这个指标是结构性的——它只查"列出的参考文献有没有在正文出现过"， 不查"这条引用是否真的支撑它所在的那句话"。 旁边那个描述性字段更有信息量：citation_coverage = 0.426。

检索层：三成预算重复覆盖

管线每次研究只搜 4 次（原 query + 3 个子查询），每次取 5 条结果。 重复的 URL 在抓取前就被去重函数滤掉，所以下游任何一级测到的重叠都恒为零—— 去重函数本身是唯一还能看见浪费的地方。

"空转检索"指一次检索的 5 条结果全部是已见过的 URL，净新增为零。20 次运行，总花费 $0.031。

是规划器不稳，还是题目不需要分支？

重复同一道题可以把两者分开：同题多次的波动来自规划器本身，题目之间的差异来自题目特性。

方差来源标准差含义
同题重复0.082规划器的运行间不稳定性
跨题差异0.075题目本身的分支难度
比值1.10两者贡献几乎相等
规划器确实不稳定：同一道题跑 5 次产出 5 组不同的子查询（finance 为 4 组）。但题目特性贡献了同样多的方差，所以两个解释都对，各占一半。
一个被推翻的机制解释

直觉上，浪费应当来自规划器复述原题——它确实经常这么做，而管线又会单独再搜一次原 query。 但把"最相似子查询与原题的余弦"和重叠率做相关，得到 r = −0.034，几乎零相关。

反例很干净：finance 的子查询区分度最高（余弦 0.769，明显不是复述），重叠率却排第二高； ai_tech 余弦 0.950，重叠率却最低。 真实机制更可能是：即使子查询在语义上区分良好，检索器仍返回同一批页面—— 每查询只取 top-5，同主题下不同措辞的 top-5 高度重合。

这个修正改变了修法：不是让规划器措辞更有区分度（finance 已经很有区分度了）， 而是加大单查询深度，或在检索前于查询层面去重。

抓取失败不是随机的

这是本次调查最硬的一条发现，判定完全基于确定性规则表，不依赖任何 LLM 判断。

来源分组 URL 数 抓取成功 失败率

其余（.com / .org / 未知）362822%

被规则表归入"其余"的失败源里还有 sciencedirect.com、ieeexplore.ieee.org、mdpi.com、mayoclinic.org——按实际权威性算，13 次失败中有 10 次是权威源。

失败原因日志写得很清楚：congress.gov 返回 HTTP 403， pmc.ncbi.nlm.nih.gov 返回反爬挑战页，itsartlaw.org 返回 429。 默认 SCRAPER="bs" 是纯 BeautifulSoup + HTTP GET，不渲染 JS、不处理反爬， 而权威机构的反爬恰恰最严。

指标与架构的交互

source_authority 的计算基数是 visited_urls，其中 30% 从未成功抓取。 这些高分源（1.0、0.9）高于均值 0.712，把平均分拉高了—— 实际读到的证据权威性只有 0.646。

也就是说：抓取器越差，指标越好看。 指标本该抓到这个缺陷，却在替它掩盖。这条已修复——源指标现在只对实际加载成功的页面打分。

该模式在三次独立运行中复现：第二次失败的是 mdpi、dl.acm.org、sciencedirect； 第三次失败的 7 个里有 5 个是 pmc.ncbi.nlm.nih.gov、pubmed.ncbi.nlm.nih.gov、sciencedirect.com、mayo.edu。

对照实验

source_diversity 的退化期望可以从退化函数本身解析推导，独立于指标实现。 拿它当真值对照：15/15 全中，平均误差 0.02 个百分点。

也就是说这个指标是精确的，朴素口径下那 6.5% 的"误差"完全来自我们用了错误的期望模型。 区分"指标不准"和"期望模型不对"是必须的，否则会冤枉一个完全正确的指标。

数据可信度边界

  • 样本量分层。A5 有 20 次运行支撑，抓取率整体值同样（20 次均值 0.680，范围 0.333–0.929）。但 A1 的按权威性分组那个 3.2 倍仍只基于 43 个 URL——那批运行才存了 URL 明细。指标面板与消融实验为 3 个 query。
  • 历史 benchmark 日志已作废。17 份日志是用有缺陷的指标测的，且未存报告原文，无法用修复后的指标重新打分。这个问题已修——benchmark 现在持久化 report 与 context。
  • grader 混杂。压缩层扫描用 mini（需扫四个条件），主面板与消融用 turbo。跨表比较绝对值无效。
  • 捕获运行的 researcher LLM 是 gpt-4o-mini，非仓库默认。管线结构参数全部为默认值，故结构性结论不受影响。
  • 成本未全程计量。$0.044 是研究调用的实测合计；grader 侧为估算。
最便宜的下一步

A5 已经用 20 次运行、$0.031 做扎实了。同样的做法可以补上 A1 最后的缺口—— 重跑一批并保留每个 URL 的域名与成败，把"权威源失败率 3.2 倍"从 43 个 URL 扩到几百个。 按现在的单次成本，约 $0.03。
